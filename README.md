# Nightshift Bass

**Download:** these plugins come with NightShift's free installers for Windows and Mac, on the
[NightShift releases page](https://github.com/ExfilBravo/nightshift/releases/latest).
Free software under the GNU GPL v3 or later ([LICENSE](LICENSE)).

Two bass distortion plugins (VST3, Windows) in the Nightshift family, built on JUCE:

| Plugin | What it does |
| --- | --- |
| **Nightshift Bass Drive** | clean-blend bass overdrive: gate, compressor, drive with grunt / attack / character voicing, tone, blend, graphic EQ, cabinet |
| **Nightshift Bass Split** | multiband bass drive: clean compressed lows, separately driven mids and highs, draggable crossovers, graphic EQ, cabinet |

Both end in the same six-band graphic EQ and cabinet section: four built-in cab voicings (4x10,
8x10, 1x15, 2x12) or any cab impulse response file you load (LOAD IR; level-matched to the
built-ins, remembered with the session). The design, parameters and the measurements each plugin
must meet are in [SPEC.md](SPEC.md).

## Building

Needs Visual Studio 2022 Build Tools (C++ workload with CMake) and the Nightshift checkout next door,
whose JUCE this project uses (`-DJUCE_DIR=...` to point elsewhere).

```bash
build.cmd Release
```

Builds both plugins and `basstool`, and copies each `.vst3` to `%LOCALAPPDATA%\Programs\Common\VST3`
(no admin rights needed; add that folder in FL Studio's plugin manager, or in Nightshift's scanner).
One plugin in its own build tree: `build.cmd Release NightshiftBassDrive_VST3 drive`.

Outputs land in `build\<tree>\<Target>_artefacts\Release\VST3\<Name>.vst3` and
`...\Standalone\<Name>.exe`. The standalone exe is also a quick way to play through a plugin
without a DAW: run it, pick the MiniFuse's ASIO driver in its settings.

## Checking a plugin without ears

`basstool` loads the built VST3 like a DAW would:

```bash
basstool --signals testdata\signals
basstool --params "build\Release\NightshiftBassDrive_artefacts\Release\VST3\Nightshift Bass Drive.vst3"
basstool --render <plugin.vst3> testdata\signals\bassdi.wav out.wav --set Drive=70 --set Cab=Off
basstool --measure out.wav --thd 82.4 --alias 1490 --crest --peakpos
basstool --measure out.wav --response --ref testdata\signals\noise30.wav
basstool --validate <plugin.vst3>
basstool --cpu <plugin.vst3> --block 32
```

`--validate` checks loading at 44.1/48/96 kHz, determinism, block-size invariance, bypass
(latency-aligned, click-free), state round-trip, parameter sweeps and silence. `--alias f0` reports
the worst non-harmonic spur of a driven sine; `--cpu` reports the share of one core at a given block
size, and the latency.

Each plugin's standalone exe takes `--snapshot gui.png [--set Name=value]` to capture its window
offscreen, and `--render in.wav out.wav [--ir cab.wav] [--set ...]` to run a file through the
processor directly, IR included.

These are GUI-subsystem programs: from PowerShell use `Start-Process -Wait` or pipe to `Out-String`
so the shell waits for them.

## Layout

- `common/` – look-and-feel, widgets (key switches, EQ faders, cab picker, footswitch), DSP building
  blocks (`BassDsp.h`: biquads, ADAA clippers, compressor, gate), the tone stage (`BassTone`: graphic EQ
  and cabinet), and the processor and editor base classes.
- `plugins/drive/`, `plugins/split/` – one folder per plugin: processor and editor.
- `tools/basstool/` – the host harness and measurements.
- `tools/standalone/` – the custom standalone app with the snapshot and render modes.
- `testdata/` – test signals (generated by `basstool --signals`).
